# Deploying the API + YouPI gateway on Render

The movie API and the embedded YouPI PG gateway run in **one process** (`server/src/server.js`).
That process exposes everything the Android observer needs on a single HTTPS origin:

```
https://<service>.onrender.com/health                     movie API
https://<service>.onrender.com/api/v1/...                 movie API
https://<service>.onrender.com/youpi/api/v1/...           payment core (observer ingest, pairing)
https://<service>.onrender.com/checkout/<paymentId>       hosted UPI checkout
https://<service>.onrender.com/youpi/admin                merchant admin / device pairing
```

> This replaces the Vercel deployment of the API. Vercel cannot run the gateway:
> it spawns local HTTP servers, writes `vendor/youpi-pg/data/.secrets`, and keeps
> long-lived pollers. The client (Vite SPA) can stay on Vercel.

## 1. Prerequisites

- The movie database is already Supabase. Copy `DATABASE_URL` from your existing `.env`.
  The gateway creates its own SQLite database on the disk, so there is nothing else to
  provision.
- A paid Render instance type is required for the persistent disk.
- Free instance types spin down after 15 minutes of inactivity. The observer needs an
  always-on process, so use **Starter** or higher.

## 2. Create the service

### Option A — Blueprint (recommended)

1. Push this repo (it contains `render.yaml` and `server/vendor/youpi-pg/package.json`).
2. Render Dashboard → **New → Blueprint** → connect the repo.
3. Render reads `render.yaml`, asks for the values marked `sync: false`, then deploys.

### Option B — Manual web service

| Setting | Value |
| --- | --- |
| Root Directory | `server` |
| Build Command | `npm ci && npm run build` |
| Start Command | `npm start` |
| Health Check Path | `/health` |
| Disk mount path | `/opt/render/project/src/server/vendor/youpi-pg/data` |
| Disk size | 1 GB |

`npm run build` installs the vendored gateway workspace (`@youpi/common`, `@youpi/db`,
`@youpi/core`) into `vendor/youpi-pg/node_modules`. Without it the gateway crashes with
`Cannot find package '@youpi/common'` — the exact failure seen on Vercel.

The disk is mandatory. It holds the gateway's SQLite database (merchants, payment
sessions and paired devices) plus its fallback `.secrets` and WhatsApp session. Losing
it means every Android device has to be paired again, even though the env-provided
secrets stay stable.

### Two databases, on purpose

| Component | Store | Why |
| --- | --- | --- |
| Movie API (bookings, users, seats) | Supabase Postgres via `DATABASE_URL` | Shared with the existing data |
| YouPI gateway (merchants, payment sessions, paired devices) | SQLite at `vendor/youpi-pg/data/youpi_pg.sqlite` | The vendored gateway's SQL is SQLite-native |

Do **not** point `YOUPI_DATABASE_URL` at Supabase unless you have audited the gateway's
queries: it uses integer boolean flags and `datetime('now')`, which the Postgres schema
does not accept. The gateway still calls the movie API's Postgres webhook handler over
loopback, so booking confirmation works normally.

The movie schema is already applied to Supabase. `database/full_schema.sql` is a
**destructive clean-slate script** (it drops every table), so do not run it against the
existing database, and the Render service deliberately has no pre-deploy migration.

## 3. Environment variables

Values in **bold** must be set by you; the rest are already in `render.yaml`.

| Key | Value |
| --- | --- |
| `DATABASE_URL` | **Supabase Postgres connection string** |
| `APP_BASE_URL` | **Customer web app origin** (the Vercel project that serves `client/`, e.g. `https://<your-client>.vercel.app`). Do not use the old API Vercel URL: its root is 404. |
| `YOUPI_UPI_ID` | **Your real UPI VPA**, e.g. `name@okaxis` |
| `YOUPI_PAYEE_NAME` | Payee name shown in the UPI app |
| `YOUPI_FRAME_ANCESTORS` | **The same customer web app origin**, allowed to embed the checkout page |
| `SUPABASE_URL` | Supabase project URL (poster uploads) |
| `SUPABASE_SERVICE_ROLE_KEY` | Service role key (poster uploads) |
| `NODE_ENV` | `production` |
| `RUN_WORKER` | `true` (seat-hold expiry + delayed publishing + email outbox) |
| `YOUPI_ENABLED` | `true` |
| `YOUPI_DATABASE_URL` | `sqlite` (gateway data on the disk; see "Two databases" above) |
| `YOUPI_ALLOW_ADMIN` | `true` (lets the panel call `/youpi/api/v1/admin/*` through the public proxy) |
| `YOUPI_ALLOW_DEV_TOOLS` | `false` |
| `YOUPI_EXPOSE_DEV_OTP` | `false` |
| `JWT_SECRET` / `JWT_REFRESH_SECRET` | generated by the blueprint; keep stable |
| `ADMIN_TOKEN` | movie admin token; generated by the blueprint |
| `ADMIN_API_TOKEN` | token you paste into `/youpi/admin`; generated by the blueprint |
| `YOUPI_WEBHOOK_SECRET` | HMAC secret for gateway → movie API webhooks; generated |
| `OBSERVER_API_TOKEN` | only needed for token-mode observers; generated |
| `DEVICE_CREDENTIAL_KEY`, `ANDROID_ENROLLMENT_SECRET`, `BLIND_INDEX_KEY`, `INTERNAL_SERVICE_TOKEN` | generated; **never change once devices are paired** |

Leave `YOUPI_PUBLIC_BASE_URL` unset. The gateway falls back to Render's
`RENDER_EXTERNAL_URL`, so checkout links and the Gmail OAuth callback use the public
HTTPS origin automatically. Add it in the dashboard only if you put a custom domain in
front of the service.

`EMAIL_PROVIDER=console` is in the blueprint, so ticket emails are only logged. To send
real mail, set `EMAIL_PROVIDER=smtp` plus `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`,
`SMTP_PASS` and `EMAIL_FROM` in the dashboard.

Do not set `PORT` or `YOUPI_API_URL`; both are derived at runtime.

## 4. Verify the deployment

Replace `<svc>` with your service host.

```bash
curl -s https://<svc>.onrender.com/health
# {"ok":true}

curl -i https://<svc>.onrender.com/youpi/api/v1/pollers/active-window
# HTTP/1.1 401 Unauthorized  +  {"error":"Unauthorized","code":"AUTH_REQUIRED"}
# 401 proves the gateway booted. A 500 here is still the old failure.

curl -s -o /dev/null -w "%{http_code}\n" https://<svc>.onrender.com/youpi.js
# 200 (checkout SDK is being served)

curl -s -o /dev/null -w "%{http_code}\n" https://<svc>.onrender.com/youpi/admin
# 200 (merchant admin panel)
```

Open `https://<svc>.onrender.com/youpi/admin`. When it asks for the **Admin token**,
paste the value of `ADMIN_API_TOKEN` from the Render dashboard.

## 5. Pair the observer app

1. Admin panel → **Services → Android SMS Companion App** → copy the **Enrollment Secret**
   (or scan the QR). The QR's `serverUrl` points at the internal loopback port, so the
   app deliberately ignores it.
2. In the app: **Settings → Gateway base URL** → `https://<svc>.onrender.com/youpi`
   (no trailing slash, do **not** append `/api`).
3. **Pair device** → paste the enrollment secret. This calls
   `POST /youpi/api/v1/pollers/android/pair` and stores a device signing key.
4. Toggle the observer **on**, grant **SMS** and **notification** permissions, and set
   the app to **unrestricted battery** usage (Android kills background receivers otherwise).
5. **Settings → Send test observation**. A `400` with `NO_ACTIVE_SESSION` is a **pass**:
   the device signature was accepted but there is no live checkout to match. `401` or
   `403` means the pairing/signature failed. Start a checkout to see an accepted
   observation, and confirm the device appears in the panel's device table.

The APK download button in the panel still serves the old 295 KB placeholder APK. Install
the Flutter app from `pay/` (`flutter build apk --release`) until that file is replaced.

## 6. Point everything at the new origin

After verifying, update:

| App | Where | Change |
| --- | --- | --- |
| Customer web | Vercel → Project → Settings → Environment Variables | `VITE_API_BASE_URL=https://<svc>.onrender.com`, then redeploy. `client/.env` is git-ignored, so editing it locally does not change the Vercel build. |
| Admin Flutter app | `admin_app/lib/services/api_config.dart` | `https://<svc>.onrender.com/api/v1` |
| Observer app | Settings screen (or `ObserverStore.kt` for a fresh install) | Base URL `https://<svc>.onrender.com/youpi` |

Then **delete or pause the old Vercel API project**. It only served the API (its `/`
is a 404) and it cannot run the gateway; leaving it up just gives the client two
different backends. Keep the client's Vercel project.

## 7. Troubleshooting

- **`Cannot find package '@youpi/common'`** — the build did not run `npm run build`, or
  `vendor/youpi-pg/package-lock.json` is out of sync. Run `npm install` in
  `server/vendor/youpi-pg` locally and commit the lockfile.
- **`/youpi/*` returns 503 `Payment gateway is disabled`** — `YOUPI_ENABLED` is `false`.
- **`/youpi/admin` returns 404** — `YOUPI_ADMIN_ENABLED` is `false` (default true).
- **Pairing returns 400 `Invalid or expired enrollment token`** — regenerate the secret
  in the panel. If you rotated `ANDROID_ENROLLMENT_SECRET`, old secrets stop working.
- **Paired device starts returning 401** — `DEVICE_CREDENTIAL_KEY` changed. Restore the
  original value and redeploy, or generate a new enrollment secret and re-pair.
- **Observer shows `failed` on HTTP 0** — Render service is asleep or the base URL is
  wrong. Check the URL includes `/youpi`.
- **Checkout page returns 500** — the gateway failed to boot; check Render logs for
  `[YOUPI] gateway failed to start`.
